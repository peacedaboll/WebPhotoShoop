# Стратегия тестирования

## Цель и границы

Проверить основной путь: открыть файл → изменить изображение → отменить ошибку → экспортировать результат. Приоритет имеют сохранность текущего документа при отказе, корректность истории, состав экспортируемых слоёв и понятные сообщения. Версия 0.1 не имеет регистрации и серверного хранения, поэтому тесты пользовательских аккаунтов к ней неприменимы.

## Уровни

| Уровень | Область | Подход |
| --- | --- | --- |
| Статическая проверка | Типы и связи модулей | `tsc --noEmit` в `npm run build` |
| Модульный | История, размеры, пиксельная коррекция | `node:test` через tsx; эталонные массивы и граничные значения |
| Интеграционный | Сервер, сборка, API | Реальный временный HTTP-порт; проверка статусов, MIME и ограничения путей |
| Системный | Полный путь пользователя | Браузер, импорт реального файла, действия, скачивание и открытие результата |
| Совместимость | Браузеры и размеры экранов | Матрица фактически проверенных сред, отдельные статусы эмуляции |
| Нагрузочный | Память, большие изображения | Пока запланирован; измерять память, задержки и устойчивость |
| Доступность | Клавиатура, фокус, контраст | Ручной обход и скринридер на следующем этапе |

Автоматизируются устойчивые правила обработки данных и HTTP. Визуальные состояния и реальный экспорт дополняют их ручной проверкой. Положительный HTTP-ответ не считается доказательством исправности Canvas, а успешная сборка не подтверждает поддержку Safari.

## Начало проверки

- Установлены зависимости по lock-файлу.
- Выбран конкретный коммит, версии среды и порт.
- `npm run build` завершается успешно.
- Есть PNG/JPEG/WebP с известными размерами, прозрачностью и цветами, а также повреждённые и неподдерживаемые файлы.
- Для каждого сценария определены ожидаемый результат и способ сверки.

## Окончание проверки и выпуск

Для учебного выпуска обязательны успешная сборка, все автоматические тесты и базовый путь в хотя бы одной указанной среде. Не допускаются известные ошибки, из-за которых обычный импорт или экспорт не работает. Остальные риски должны иметь запись в техдолге. Для публичного сервиса дополнительно потребуются закрытие P1, проверка целевых браузеров, автосохранение и испытания нагрузки; текущая версия этого критерия не достигла.

При найденной ошибке фиксировать шаги, файл, размеры, среду, ожидаемый и фактический результат. После исправления повторять связанный сценарий и необходимые регрессионные проверки. Не заменять статус «не проверено» предположением о поддержке.

## Тестовые данные и регрессия

Хранить небольшой набор собственных файлов: прозрачный PNG 2 × 2 с известными каналами, фотографию JPEG с ориентацией EXIF, WebP с прозрачностью, однотонное изображение для яркости и большой файл у границы лимита. EXIF, профили цвета и кодеки проверяются на каждом целевом браузере, а не только на одном компьютере.

После изменений модели обязательно проверять историю и экспорт, после изменений сервера — раздачу сборки и API, после изменения CSS — обе компоновки. После изменения памяти — предельные документы и повторные отмены.

## Фактические результаты

`npm run build` — успешно. `npm test` — 7 тестов, 7 успешно. Проверены ветвление и предел истории, размеры, нейтральная коррекция, насыщенность, ограничение каналов, HTTP главной страницы и API, запрет неподдерживаемого метода и выхода за каталог, HEAD и 404.

Снимки реального приложения находятся в `docs/verification`, проектные макеты — в `docs/prototypes`. Экспортированный PNG проверен по декодированным размерам. Эталонное попиксельное сравнение композиции, производительность больших файлов и полный набор браузеров ещё не проверены.
