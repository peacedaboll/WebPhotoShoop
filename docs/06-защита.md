# Задание 6 — анализ защиты

Фронтенд публичного веб-приложения загружается в браузер. HTML, CSS и JavaScript доступны посетителю, а исходники этого проекта опубликованы на GitHub. Минификация, обфускация, запрет правой кнопки и проверка домена в клиенте не предотвращают копирование: пользователь контролирует браузер и может удалить проверку. Серийный номер в JavaScript тоже извлекается вместе с кодом.

Лицензионное соглашение определяет условия использования, но не блокирует техническое копирование. Проверка лицензии на сервере защищает доступ к серверным функциям; привязка к оборудованию подходит отдельным desktop-программам и неудобна для веб-редактора. Перенос обработки фотографий на закрытый сервер изменил бы архитектуру и условия конфиденциальности. На данном этапе защита от копирования не вводится: редактор сознательно обрабатывает изображения на устройстве.

Защищаемые данные следующего этапа — email, хеш пароля и сеансовые токены. Пароли следует хранить как медленные хеши с индивидуальной криптографической солью, а не шифровать обратимо и не заменять быстрым SHA-256. Выбран scrypt из стандартной библиотеки Node.js с параметрами N=131072, r=8, p=1. Рекомендации сверены с OWASP Password Storage Cheat Sheet 10 ноября 2026 года.

Сессия должна храниться в HttpOnly cookie, иметь срок действия, заменяться при входе и отзываться при выходе. На сервере достаточно хранить SHA-256 случайного токена: высокая случайная энтропия отличает токен от человеческого пароля. SameSite и проверка Origin ограничивают межсайтовые запросы; частота входов и объём тела ограничиваются. Хеши, пароли и cookie не записываются в журналы. Файл учётных записей и его резервные копии исключаются из Git, доступ к ним ограничивается средствами ОС. Для реального размещения нужен HTTPS с Secure cookie. Учебный HTTP на localhost не защищает трафик локальной сети.

Сами изображения не отправляются серверу и остаются в памяти вкладки. Удаление вкладки приводит к потере несохранённых изменений; экспорт пользователь выполняет самостоятельно. Это описание модели защиты, а не заявление об отсутствии всех уязвимостей. Реализация и проверки авторизации относятся к заданию 7.
